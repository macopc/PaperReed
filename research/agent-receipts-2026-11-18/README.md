# 草稿回执和发送恢复复测

基线是 [上一轮 8 个任务](../agent-cases-2026-11-18/README.md)，源码基点为 `1037d28`。本轮把 [0049 补丁](../patches/0049-agent-draft-and-send-receipts.patch)构建为独立的本地 0.0.1 应用，测试使用它安装的 CLI。原发布包仍可用于复现基线。

建稿和回复的成功回执增加 `status: "saved"`，回复回执也包含主题。写入使用原有保存调用，回执在保存成功后返回。需要看正文时用 `draft-get` 读取。已有发送操作编号时查询 `operation-get`；若首次提交的回执丢失，则用原草稿、修订号和 requestId 重放。CLI 帮助、连接失败提示、桌面复制给 Agent 的交接文字及使用说明采用同一恢复流程。两项改动都复用了已有协议。

验证沿用基线的任务原话、两个本机 IMAP/SMTP 邮箱和相同合成数据。每项从新的 Codex CLI 会话开始，收到草稿任务的会话另有草稿引用。编号 5 / 5a 是并发 / 普通改稿，8 / 8b 是正常发送 / 丢失首次回执。丢回执指已经提交但调用方没有拿到结果。并发方通过共享草稿服务修改日期。每个变体执行一次。

- [调用与回执](cli-trace.jsonl)及各编号对应的 prompt、answer 保存原始输入和结果。丢回执注入同时记录已被扣下的真实返回值。
- [持久草稿、附件与发送账本](mailbox-check.json)、[发送前](before-send.json)及[最终服务器状态](final-server.json)用于独立核对。
- [桌面草稿截图](reply-review.png)来自重新打开的测试配置副本。
- [发送帮助](draft-send-help.txt)、[建稿帮助](draft-reply-help.txt)和[连接中断错误](connection-error.json)来自本轮客户端。错误样本使用本机关闭的监听端口。
- [构建、补丁重放与 TypeScript 检查](build-checks.log)。首次复制开发目录时，Swift 缓存记录了旧构建路径；清除测试副本的 Swift 构建缓存后构建通过。

## 结果

8 项任务、10 个独立会话全部达到本轮预期。账号识别、供应商交期（12 月 9 日）、当天两项待回复、并发日期保留（12 日）、最新版报价（USD 14,360）与附件字节、归档后单独恢复均与测试数据相符。

- **回复草稿**：上轮建稿后额外提交一次相同正文，本轮收到 `status: saved` 后只读核对一次，额外正文写入为零。数据库中只有一封关联原会话的回复草稿，并保留自动生成的原信引用。建稿阶段 SMTP 计数为零。
- **已获得发送回执**：首次返回 queued，随后按操作编号只读查询；账本最终为 accepted / filed。
- **首个发送回执丢失**：客户端在第一次返回 queued 时截断回执。Agent 用完全相同的参数再次调用 draft-send，取回同一个 operationId 并查到最终状态。两种变体各有一条发送记录和一个已发送副本，工作邮箱 SMTP 共收到两封，个人邮箱为零。

上轮在丢回执时也曾正确恢复。本轮证明说明与已有行为吻合；每项只有一次运行，不据此推断成功率提升。
