# 邮件规则与自动分类 · 实际窗口验证

本轮接通按账号配置的本机规则、自动分类、手动纠正、已有邮件预览与显式应用，以及同一接口下的 CLI。没有引入 AI 模型、额外服务或远端邮件动作。

[实际窗口](index.html) · [规则集成结果](result.json) · [置顶／稍后／标签回归](triage-regression.json) · [补丁重放](patch-check.txt)

## Before / After / Why

| Before | After | Why |
| --- | --- | --- |
| 设置页使用上游的通用规则编辑器 | 一个匹配条件、一个本机动作；新规则默认暂停 | 与首版规格对齐，减少不必要的配置组合 |
| 本机标签和分类尚未接到规则 | 发件人／主题包含 → 添加标签或设置分类 | 先让确定、可解释的重复整理自动完成 |
| 缺少可用的分类状态 | 普通、往来、通知、订阅视图；支持手动指定或重新跟随规则 | 用户可以修正规则结果，且纠正不被新来信立即覆盖 |
| 已有邮件依赖上游整箱重处理 | 最多预览 50 个会话，显示效果，再勾选应用 | 不隐式处理未看见的邮件；不移动服务端文件夹 |
| 已有预览可能与执行时状态不同 | 保存规则修订指纹及具体消息引用，应用时复核 | 规则改动或新回复到达后，需要重新预览 |
| 规则编辑容易被切页丢弃 | 未保存时暂不可切换账号、规则或设置页，提供保存／放弃 | 避免静默丢失输入，不增加确认弹窗 |

## 首版行为

- 规则按账号保存，条件为**发件人包含**或**主题包含**。发件人匹配名称和邮箱地址；字符串规范 Unicode 后按不区分大小写的子串匹配。不支持正则、正文、嵌套条件或任意脚本。
- 动作为添加一个已有本机标签，或分类为普通／往来／通知／订阅。规则按显示顺序执行，标签可累加，最后一个匹配的分类动作生效。
- 自动处理针对启用后同步到收件箱的外部来信；自己的发件、草稿、垃圾邮件和废纸篓不参与。新会话无匹配规则时保持普通；已有会话无匹配结果时保留原整理状态。
- 首次启用、编辑保存或再次启用时记录当前收件箱同步基准，不自动回填缓存历史。暂停、删除和重排不撤销已有结果。删除标签时，引用它的本机规则同时暂停。
- 手动分类会设置手动标记，后续规则仍可添加标签，但不覆盖该分类。“重新跟随规则”立即用最新外部来信计算当前分类，并清除手动标记；未匹配分类动作时回到普通。
- 已有邮件预览使用每个会话**最新一封外部来信**匹配全部已启用规则；预览本身不修改状态。默认范围 `in:inbox`，可以收窄搜索，界面每次最多展示 50 个会话，默认不勾选。CLI 单次最多 100 个明确目标。
- 应用需携带预览的规则修订值和消息 ID；规则变化返回 `rules-changed`，最新外部来信变化返回 `preview-stale`。批次逐项返回，部分拒绝不抹掉已成功项。

## 本机实现

复用 `local-triage.ts` 的现有同库写连接及顺序写入入口，在原本机会话表增加 `category` / `categoryManual` 两列，并增加：

| 表 | 用途 |
| --- | --- |
| `PaperReedLocalRule` | 按账号保存规则定义、顺序、启用状态和同步基准 |
| `PaperReedRuleProcessed` | 按账号与消息 ID 记录已执行的自动处理 |

每封消息的标签／分类写入和已处理标记在同一 SQLite 事务提交。处理标记避免同步重复事件、重新打开应用后重新加回用户已移除的标签；它也避免单一“最大已见 UID”游标跳过稍后才落库的较低 UID。每轮每账号最多处理 100 个候选，后续检查继续处理。

自动入口由数据库变化（250 毫秒合并）、每 15 秒检查、窗口重新获得焦点及应用启动触发。它与收件箱查询分开执行，不让查询等待整批分类。没有后台常驻进程；应用关闭时不处理，下次启动后继续读取符合基准的已同步来信。

同步基准使用 Inbox 的 `UIDVALIDITY` / `UIDNEXT`，排除低 UID 历史缓存。文件夹用途改变或 UIDVALIDITY 改变时停止用旧基准自动执行，设置页显示等待状态，用户重新保存启用规则后建立新基准。手动预览／应用无需依赖这个自动来信游标。

Paper Reed 模式下，上游 `MailRulesStore` 的自动处理和整箱重处理入口暂停；旧规则数据保留，不自动迁移，不再通过该设置页执行上游星标或移动动作。关闭 Paper Reed 模式并重启后保留原上游行为。已经提交的旧远端任务不会被本轮撤销。

实验迁移为按列存在性添加字段，并保留上游 `user_version`。正式迁移、清理已处理历史及账户重建后的状态映射仍随最终底座确定。

## 权限与命令

- 按账号列出规则需该账号读权限。创建、编辑、删除、排序规则会建立账号级自动化，因此需要该账号全部文件夹的写权限；不能由只获局部文件夹权限的 Agent 建立更广的规则。
- 预览和显式应用仍逐个检查账号、会话和文件夹可见范围。手动分类使用上一轮共用的本机邮件写权限。
- 保存且启用的规则是持久的用户自动化，不会因为之后关闭 CLI 连接而消失；暂停请在规则页或通过 `rule-save` 明确设置 `enabled: false`。
- CLI 增加 `rules`、`rule-save`、`rule-delete`、`rules-reorder`、`rules-preview`、`rules-apply`、`classify`、`classify-auto`；`local-list` 增加 `category:ordinary|people|notifications|subscriptions` 视图。见 [使用说明](../cli/README.md)。

## 边界

- 自动分类是用户定义的确定规则，没有内置 AI 或默认猜测分类。复杂条件、规则导入迁移、跨设备同步和后台关闭状态执行未加入。
- 仅验证单个本机文件夹型 IMAP 账号；真实 Gmail / Outlook、跨真实账号、服务商 UID 重置、长时间断网和大邮箱吞吐尚未验收。
- 离线期间尚未获知的旧来信，以及从别处导入并获得新 UID 的成员，可能在之后同步时被视作新来信；不能声称能从服务端时间上完全区分所有历史导入。
- 标签与分类属于会话，规则基于消息匹配。多个新成员依实际处理顺序更新会话；不提供跨设备人工编辑合并或长期历史撤销。
- 规则保存采用最后一次成功写入；尚无两个编辑者同时编辑同一规则时的版本冲突 UI。预览／应用有修订校验，不等于所有规则编辑都已有并发合并。
- 更改规则不会删除已经添加的标签。显式应用也保留手动分类；需要先选择重新跟随规则才能恢复分类自动更新。
