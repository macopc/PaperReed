## 本轮修复：返回列表丢失焦点

真实操作中，点击“返回搜索结果”后 `document.activeElement` 变成 `BODY`。列表命令依赖所在区域的焦点，因而无法直接继续键盘浏览。隔离打包应用同样复现：打开第 4 行再返回，预期焦点索引为 3，实际为 -1。见 [修改前失败](focus-before.log)。

[0046](../patches/0046-restore-mail-list-focus.patch) 将返回动作集中到一个方法：先按现有机制保存编辑，再切回列表，以现有选中对象的稳定 ID 找回对应邮件／草稿行并聚焦；没有对应行时聚焦搜索框。保留原有刷新和选择清理行为。没有添加焦点历史、定时器或新的状态字段。

在既有 `check-command-panel.cjs` 补充三个场景：从阅读返回原行后继续 J 浏览、新建草稿不在当前邮箱时回到搜索、已有草稿返回其原行。修改前第一个断言失败，修改后全部通过，同时原有 Gmail / Apple Mail / 自定义按键、命令面板和编辑器快捷键检查通过。真实 Gmail 再次验证邮件行与草稿行的返回焦点均正确。
