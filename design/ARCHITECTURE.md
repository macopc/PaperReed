# macOS 邮件客户端技术选型与架构

> 2026-11-15 更新：本文保留为历史技术路线候选。当前实验依据是 [首版邮件核心设计](MAIL-CORE.md)，其中已收敛标签归属、权限与草稿／任务语义。本文的具体框架、进程和存储安排仍待验证，不是实施要求。

最新比较与适配缺口见 [首版技术选型](TECH-CHOICE.md)：优先验证 Mailspring 产品分支，但不能把现有 MCP 接口当成已满足邮件核心要求。

状态：候选方案，待评审，尚未最终确定。2026-11-14。本文保留此前提出的 Mailspring 路线以供比较；仓库创建和提交不代表采用该方案。目标是日常愿意打开的 Mac 邮件客户端；外部 agent 与人共用邮件状态，内置 AI 后续接入。

**候选路线（非最终决定）**

本候选方案建议基于 Mailspring 建立产品分支，保留 Electron、React、TypeScript、SQLite 和 C++ 同步引擎。重新设计主界面，并把已有 MCP 的邮件能力开放为 CLI。采用一个仓库、一个桌面安装包、现有本地进程结构。

这是采用原生窗口与系统交互的 Electron 客户端，不是 SwiftUI 原生客户端。选择它是为了把工程投入留给阅读体验、邮件正确性和交互打磨。若最终目标变为完全原生控件、极低常驻内存，应该重新评估 SwiftUI；本轮不把这件事隐藏在后续“换壳”承诺里。

**候选选型**

| 部分 | 选择 | 理由与约束 |
| --- | --- | --- |
| 产品底座 | Mailspring 产品分支 | 已有本地同步、编辑器、统一收件箱、MCP；与上游保持可追踪差异。 |
| 桌面壳 | Electron，沿用基线版本 | 保留 macOS 原生窗口按钮、菜单、通知、文件选择与拖放。发布前更新受影响的安全依赖；不顺便迁移整个框架。 |
| 界面 | React + TypeScript | 逐步替换收件箱、列表、阅读区和设置入口；邮件渲染和编辑器先复用。 |
| 样式 | 现有 LESS + 少量语义 CSS 变量 | 统一字体、间距、色彩和状态。沿用现有组件，不引入第二套 UI 框架。 |
| 界面状态 | 现有 stores / observable queries | 选中项、滚动位置等是界面状态；邮件内容与任务以现有数据库为准。 |
| 同步与存储 | Mailspring-Sync + SQLite / 现有全文索引 | C++ 引擎保持数据库写入权；界面和 CLI 不自行修改 SQLite。 |
| 自动化 | TypeScript CLI + 已有 MCP HTTP 接口 | 一套邮件操作实现，两种接入形式。CLI 输出稳定 JSON；MCP 保持 agent 兼容性。 |
| CLI 分发 | 随 .app 打包，使用应用携带的 Electron Node 模式 | 复用上游 stdio bridge 的运行方式，用户无需额外安装 Node。安装包验收包含 runAsNode 配置与路径迁移测试。 |
| 凭据 | 现有 Keychain 路径 | 邮箱密码和 OAuth token 留在客户端；CLI 只持有本地自动化凭据。 |
| 内置 AI | 后续能力 | 复用邮件操作；已有本地模型实现可作候选，模型选择不影响基础邮件功能。 |

SwiftUI + 自建桥接层会扩大 UI 和同步核心的重接范围；Tauri + Rust 同样不能直接复用现有 Electron stores。Zero 的 Web、Cloudflare 和助手服务结构需要额外桌面化。此前方案暂未采用这三者；最终底座仍需比较和确认。

**只有三个需要明确维护的业务模块**

1. 桌面界面：导航、阅读、编辑、快捷键和本机收件箱呈现。
2. 邮件操作：查询、草稿、整理、发送、权限和任务结果。它复用现有 stores、TaskFactory 与同步桥接，集中隐藏账号差异和任务完成语义。
3. 自动化入口：CLI 参数 / JSON、MCP schema、agent 安装配置。只做输入输出适配，邮件逻辑由邮件操作模块承担。

同步引擎是已有实现，继续保持独立进程。保留其每账号工作方式，不新建守护进程、消息队列、HTTP 业务后台或云数据库。

桌面界面直接调用邮件操作；CLI 通过本机 MCP 调用同一实现。查询继续读取现有只读数据库查询层；修改必须走同步任务。C++ 的变更通知更新界面、任务状态和后续查询结果。

初期仅把需要由 UI 与 MCP 共用的逻辑从处理函数中提取到 `app/src/services/mail-operations/`。不批量重写所有旧 stores，也不叠加通用 CommandBus、依赖注入容器或插件平台。CLI 放在同仓库 `app/cli/`，继续使用原构建流程。

**邮件状态与本机呈现分开**

服务商继续保存邮件、草稿、文件夹 / 标签、已读和星标。来自不同账号的相似邮件可以一起显示，但不合并为同一个可回复对象；所有修改明确携带账号标识。

第一版的置顶和稍后处理是本机呈现状态，保存在现有插件元数据中，由同步引擎写入。它们不移动远端文件夹、不占用服务商星标，也不依赖 Mailspring 官方元数据服务。这意味着手机或另一台电脑暂时不会共享置顶和稍后处理状态。

- 置顶：让会话固定在本机收件箱上方；保持独立于已读和星标。
- 稍后处理：从当前本机收件箱隐藏；到期或收到新的外部回复时重新出现。时间保存为 UTC，按系统时区展示。退出应用期间到期的项目在下次启动时恢复。
- 聚合：联系人邮件优先逐封展示；订阅和通知按发件人 / 域名折叠。使用邮件头和简单规则，允许用户纠正。分类不确定时保留在普通邮件列表，不依赖模型判断。
- 归档、标记已读、标签与发送：仍修改真实邮箱，使用原同步路径。

本地元数据仅需要会话的 pinned、snoozedUntil 和用于识别新回复的标识；不额外建第二套邮件数据库。第一版不会自动连接官方 identity / metadata 服务。原 Snooze 中“移动远端文件夹”的行为需要改为上述本机呈现逻辑，不能仅去掉额度判断。

**自动化操作契约**

CLI 命令名暂以 `mailctl` 示意，正式产品命名时统一：

```text
mailctl accounts --json
mailctl search 'from:alice' --account <id> --json
mailctl thread <id> --account <id> --json
mailctl draft reply <thread-id> --account <id> --body-file reply.html --json
mailctl archive <thread-id> --account <id> --json
mailctl operation <operation-id> --json
```

查询结果分页并包含明确的 accountId 与对象标识。草稿操作返回可继续编辑的草稿标识。修改操作返回 operationId；多账号批量操作返回多个任务回执，不额外创建父作业系统。

任务结果区分排队、本地生效、远端完成、失败、取消、结果待确认。以现有 Task 持久记录和 delta 通知为基础；`status=complete` 仍需检查 `error`。发送的远端完成仅表示邮件服务器接受，不表示收件人已收到或阅读。

CLI 可选择等待并设置超时；等待超时不等于任务失败，回执继续带 operationId。对发送提供持久化请求标识去重，复用任务记录。遇到服务器可能已接受但响应丢失的情况，报告结果待确认，不自动再次发送。

关闭主窗口后可按设置继续后台运行；明确退出应用后 CLI 返回应用未运行，不偷偷启动另一个同步实例。第一版后台能力来自原桌面应用，而非独立 headless 产品。

**权限与邮件内容**

自动化默认关闭，用户在设置中连接 agent 时启用。沿用只读、读与草稿、读写、读写与发送四级权限，加账号与文件夹范围；设置一次后，允许范围内的操作无需逐封重复确认。权限由应用端检查，CLI 参数不能提升权限。第一版可共用一个本地授权配置，待实际需要再拆每 agent 授权。

正文保持隔离渲染、HTML 清理和受控外链打开，绝不将外部邮件放入具备 Node 权限的应用页面。agent 读到的正文是数据，不是授权指令；发送权限来自用户设置。保留现有操作审计，正常界面显示自然语言结果，诊断细节留给设置和 CLI。

**macOS 品质要求**

主界面以 13 英寸 MacBook 和桌面大屏都能舒适阅读为准，支持窗口缩放、系统深浅模式、系统字号、VoiceOver、中文输入法、原生菜单与快捷键。关闭窗口和退出应用的区别可理解；不靠常驻菜单栏插件才能收发邮件。

列表保留虚拟化，读取内容不阻塞主交互。验收关注缓存邮件切换、长列表滚动、连按归档后的选中项与滚动位置；不以大面积骨架屏或动画掩盖阻塞。性能预算在首个可运行包上测量后锁定。

首个安装包在当前 Apple Silicon Mac 上验证。最低 macOS 版本与 Intel 发布支持在打包验收时确定；可选本地 AI 通过能力检测启用，不提高基础收发邮件的系统要求。

**采用该路线时的建议实施顺序**

1. 安装包与基本闭环：独立应用标识 / 数据目录，保留原客户端数据；两个测试账号完成收取、回复草稿、归档、CLI 查询和任务结果验证。
2. 主界面与本机整理：按后续通过评审的设计实现阅读布局、快捷键、置顶、稍后处理与聚合；完善键盘、焦点、空状态和错误恢复。
3. 自动化体验：完整 CLI、外部 agent 安装配置、范围权限、发送去重和任务查询；应用退出、重启、断网恢复均有明确结果。
4. 内置 AI：在已有操作和权限上加入摘要与写作辅助，不把聊天面板变成客户端首页。

首版以独立签名 / 公证的 .app 分发，保持同一仓库。发布前完成独立 OAuth 应用配置、凭据刷新测试和同步引擎构建；上游代码采用 GPL-3.0，分发与源码一起规划。团队协作、移动端、自建邮件服务器、插件市场和跨设备本机状态同步不进入首版。

**需要通过的工程证据**

此前 8 项隔离测试证明了部分接口路径与问题，不是完整产品验收。真正进入日用前，必须验证：CLI 草稿出现在 GUI；GUI 修改后 CLI 读到同一结果；两个账号不会串用；离线任务在重启后恢复；被拒绝的发送无副作用；发送结果不明确时不会重复投递；无系统 Node 的 Mac 也能运行 CLI。
