# Agent 交接 · 交互候选（待评审）

目标：用户从正在处理的邮件开始使用外部 Agent，无需先手动查找邮件、复制标识或编写 CLI 命令。

## 入口与状态

| 状态 | 界面行为 |
| --- | --- |
| 未安装 CLI | 收件箱、搜索、会话、写信和回复区显示“连接 Agent”。点击说明安装 CLI、配置 Agent、携带当前内容这三个步骤。 |
| CLI 已安装，Agent 未配置 | 入口变为“交给 Agent”。交接面板保留当前范围与任务，提供配置入口。 |
| Agent 已配置 | 确认范围和任务后交接；配置过程中返回原会话 / 草稿，不丢失上下文。 |
| 访问关闭 / 邮箱未授权 | 保留任务与范围，说明原因并提供设置入口；禁用交接。 |

安装成功应由真实检测结果驱动，不能因点击安装按钮就视为成功。本轮原型提供“预览安装完成态”和“模拟连接”，仅供检查界面状态。

## 上下文

- 列表：有勾选时使用选中邮件，否则使用当前可见筛选结果与账号范围；只带入已授权邮箱对应的邮件，并明确告知纳入数量，不默认代表全部历史邮件。
- 会话：当前会话与准确的账号标识。
- 写信：当前草稿及发件账号。
- 回复：当前会话和未发送的回复草稿。
- 在启动前显示范围与可编辑任务。默认任务产生建议或草稿，不要求直接发送。
- 进入连接配置再返回时，保留任务文字、所选邮件与回复编辑状态；回复草稿仍属于同一次交接。
- 设置页的安装引导不绑定任何邮件。安装预览完成后显示就绪状态，交接从邮件、搜索结果或草稿发起。
- 一次任务不得扩大设置中的授权。写回草稿或整理需要对应权限；发送仍受独立权限限制。

## 这轮不锁定的工程细节

CLI 安装位置、安装命令、签名更新策略、版本检测、是否使用终端 / 深链 / Agent API 唤起、上下文传递协议，以及结果如何写回客户端。

后续再针对相关客户端的官方接入方式验证。此轮没有声称已实现或验证任何同类产品的安装协议，也没有编造可执行命令。

共用操作、草稿修订、账号权限与发送结果的当前提案见 [首版邮件核心设计](MAIL-CORE.md)。不为交接额外建设独立邮件后台；最终结构随技术验证确认。
