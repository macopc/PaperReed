# 实施质量修复验证

对应 [质量审查](../quality-review-2026-11-16/README.md) 和 [0021 补丁](../patches/0021-quality-lifecycles.patch)。审查报告已先提交并推送为 `8611b0f`；以下是之后的修复。继续使用既有客户端、SQLite、原生 Task 和保存回执，不增加服务进程、持久任务表、锁管理器或重试框架。

## 改动

| 审查问题 | 修复后的行为 |
| --- | --- |
| 保存期间继续编辑，关闭丢输入 | 保存后检查 dirty；最终关闭前核对各会话保存时的内容和待加入附件。取消 15ms 延迟关闭，有新输入就保留窗口。发送前也检查保存期间的新编辑。冲突另存路径仍允许保存副本后关闭。 |
| 附件错误被第一个等待者消费 | 等待者观察原添加 Promise 的 rejection。UI 展示并确认失败后结束该尝试；读取错误不再改变状态。队列尾部单独恢复，让后续添加正常执行。没有独立的错误缓存。 |
| 列表读取依赖全局整理队列、逐行重复查询 | 列表不再启动或等待稍后扫描；到期过滤按查询时间计算。状态用一次批量 Thread 查询、两次本机查询读取；摘要用一次批量查询。授权仍在异步读取后检查。 |
| 后台扫描长期占用写队列 | 稍后和规则的异步扫描在队列外进行，仅提交结果时复用现有写队列。稍后更新匹配扫描时的状态；规则修订变化后不提交旧扫描结果。同步 SQLite helper 不再伪装成 async。 |
| pending 只能靠轮询释放 | 保持立即返回 queued；已有原生受理回执负责释放临时去重记录。任务状态查询不再承担内存清理职责。 |
| 附件永久保留 | 启动时一次性清理未引用的 `local-xxxxxxxx-xxxx` 附件目录。保存的邮件、未完成 Task、未解决发送记录保留引用；有活动编辑会话／写信窗口时跳过。候选目录在读数据库前固定，不回收期间新创建的文件。 |
| 错误被吞、保存成功重复断言 | 发送结果读取失败会记录错误并显示暂不可读，不继续展示陈旧结果。共享保存服务返回明确成功回执，编辑会话直接使用；原生边界继续检查保存状态和修订回执。 |
| 检查依赖 ignored 脚本 | 新增固定基线 [准备／重放／类型检查入口](../../scripts/prepare-desktop.py)，CI 使用同一命令。没有搬迁整份上游源码。 |

附件清理有意留到下次启动：运行中的未保存版本仍可能需要旧文件；保存受理结果不确定时也不立即删除。本轮不引入引用计数、定时 GC 或“失败即删”的推断。正式原生引擎构建和真实邮箱验收仍是另外的工作；CI 的类型检查不代表可发布安装包。

## 验证

[定向结果](result.json) 使用真实 Electron 窗口、CLI、原生引擎和隔离本机 IMAP / SMTP：

- 暂缓实际保存回执，在关闭等待期间继续输入：窗口保留；第二次关闭后重新读取草稿，后续输入完整。
- 实际导入不存在的文件：两个等待者均失败；确认错误后同一草稿可正常添加附件。
- 8 个会话的状态读取：单条 Thread 查询从 16 次降为 0 次，改为一次批量读取。
- 暂缓一次置顶写操作的正常读取：收件箱和标签读取均可独立完成。
- 原生整理任务完成后，在 CLI 尚未查询状态时，pending 已为 0。
- 两次完整重启：孤立导入被回收；保存的草稿附件和非应用目录保留；移除附件后在下一次启动回收旧文件。

既有流程回归：

- [附件／CLI／账号颜色](attachments-regression.json)：独立恢复副本、重启恢复、缺附件拒绝发送、发送快照、GUI／CLI 实际发送；本机 SMTP 共 2 次，核对真实 MIME 附件字节、收件人、回复头和 Bcc。
- [规则／自动分类](rules-regression.json)：新邮件触发、手动纠正优先、规则排序、暂停与重新启用、重启不重复、账号与文件夹权限。
- [收件箱整理／搜索](inbox-regression.json)：归档、垃圾箱、批量已读与精确撤销、重复请求去重及权限边界。
- [关闭冲突与恢复](recovery-regression.json)：保留未保存输入、另存副本并关闭、重启重开；SMTP 为 0。
- [置顶／稍后／标签](triage-regression.json)：查询排序、过滤、到期与重启唤醒、新回复唤醒、历史 UID 忽略、垃圾箱不恢复、权限边界。

[补丁检查](patch-check.txt)：固定基线重放全部 21 份补丁，72 个修改文件与真实测试 checkout 逐字节一致；CLI 副本一致。干净锁文件安装后的完整 TypeScript 检查通过；仓库 58 项 JS 语法、JSON、Markdown 链接和 12 个设计预览一致性检查通过。本地 Node 版本为 24.15.0；新增 CI 配置使用 Node 22，尚未推送触发云端运行。

所有测试仅使用隔离的本机测试账号，未访问用户真实邮件。

## 复现

新目录准备及完整 TypeScript 检查（Node.js 22+、Git、Python 3.10+）：

```sh
python3 scripts/prepare-desktop.py /tmp/paper-reed-check --typecheck
```

已有可运行实验 checkout 与本机协议测试环境时，运行本轮定向回归：

```sh
PAPER_REED_QUALITY_CHECK=1 sandbox-exec -f research/harness/loopback-only.sb \
  research/.local/venv/bin/python research/harness/check-compose-handoff.py \
  --upstream research/.local/Mailspring --controls
```

准备脚本只准备源码和类型检查依赖，不编译原生引擎、安装 Electron 运行时或设置协议测试服务。
