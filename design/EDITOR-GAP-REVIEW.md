# 编辑器与副本辨识：设计差异评审

对照基线：`design/direction.html` 当前写信／会话页和 `INTERFACE.md`；实际基线：`4685f9a` 的真实 Electron 截图。以下先描述差异，不把可运行等同于设计完成。

| Before：实际实现 | After：目标 | Why：影响与边界 |
| --- | --- | --- |
| 通用“写一封信”标题占据最高层级，真实主题在表单最下方 | 主题直接作为 26px / 38px 可编辑标题，长主题换行；回复不重复会话标题 | 收件人和正文按阅读顺序排列，减少无效标题 |
| 收件人在前、发件人在后；字段偏移约 22px，正文贴版心左边 | 发件人在前，字段标签和正文共用 640px 版心；标签列固定，值列对齐 | 让回复与写信属于同一结构；改变视觉次序也要同步 DOM／Tab 次序 |
| 中英文混杂，收件人用较重灰色控件，格式工具栏一直展开 | 常用标签中文化，弱化收件人边框，格式由明确按钮展开 | 不删除输入校验、收件人补全、抄送／密送和已有内容 |
| 左侧发送，附件和插件图标密集 | 附件、格式在左；Agent 上下文与发送在右；次要动作进入更多菜单 | 沿用设计稿操作层级，保留现有发送和附件处理 |
| 保存提示独占较高区域，冲突后再叠加全页提示 | 常态只占一行；冲突在编辑器内显示操作；恢复后旧提示消失 | 不重复报错，不将未保存误称为已恢复 |
| 同主题原稿与恢复副本完全一致，重启后来源不可辨 | 草稿行显示“恢复副本 1 / 2”、保存时间；打开后显示来源及“查看原稿” | 标记属于本机元数据，不改邮件主题，不写进邮件头，不上传给收件人 |
| 复制成功后再输入会产生更新版本，但列表没有区别 | 每份副本有稳定编号及创建时间，来源关联稳定，原稿不可用时明确说明 | 不自动覆盖原稿、不把“副本”伪装成邮件服务商同步状态 |

## 实现范围

复用原有编辑器、收件人字段、附件与共享邮件核心。副本来源使用现有本机数据库的一张小表，只保存账号、草稿标识、原稿标识、原稿版本、创建时间及递增编号；不建立新的同步服务或通用版本系统。来源记录由同步引擎在副本保存的同一事务中写入；保存失败一起回滚。界面只读现有数据库，且只展示仍存在的草稿，已删除副本不会成为可见的假草稿。编号按同一账号、同一原稿递增，删除较早副本不重排编号。旧版未记录来源的副本不根据主题猜测身份。

复制后继续编辑、恢复时又输入、源草稿已删除、重启后打开、相同主题多份副本、跨账号边界需要验证。含附件的恢复副本仍明确不支持，不静默丢附件。
