# 置顶、稍后与本机标签 · 实际窗口验证

本轮接通 Paper Reed 实验工作台的本机整理：列表与阅读页操作、持久状态、到期／新来信恢复、标签管理，以及 GUI / CLI 共用接口。继续使用现有本地邮件底座，不要求重编译同步引擎。

[实际窗口](index.html) · [本轮集成结果](result.json) · [收件箱回归](inbox-regression.json) · [补丁重放](patch-check.txt)

## Before / After / Why

| Before | After | Why |
| --- | --- | --- |
| 收件箱按日期排列，没有本机置顶 | 置顶优先排序、“置顶”视图、阅读页及批量取消 | 优先事项独立于服务商星标，筛选与排序在分页前完成 |
| 稍后入口尚未接入 | 3 小时后、明天 09:00、自定义时间；稍后视图可结束或改期 | 临时移开待办邮件，保留原远端位置 |
| 自定义标签还停留在设计 | 本机标签创建、改名、改色、删除、批量添加／移除和筛选 | 跨账号共用词汇，不依赖某个邮箱的标签机制 |
| 新标记容易把列表挤成三行 | 标签与稍后时间收在第二行；最多显示两个标签和余量 | 保持两行节奏；侧栏与邮件用同一色点，文字保持中性色 |
| Agent 只能得到普通文件夹查询 | 本机视图交接生成 `local-list`，选中项仍是精确会话引用 | 不把本机标签误当成服务商文件夹 |

## 行为约定

- **置顶**：仅影响 Paper Reed 的排序和置顶视图，不修改星标、已读或服务端文件夹。不把已归档邮件移回收件箱。
- **稍后**：仅支持仍在收件箱且不在垃圾邮件／废纸篓的会话；从本机收件箱隐藏，普通搜索仍可找到。绝对到期时刻持久保存，按系统时区显示；“3 小时后”为实际经过三小时，“明天 09:00”为下一个本地日历日的九点。
- **恢复**：到期、新的外部来信，或手动“结束稍后”解除隐藏。自己发出的回复不触发。已经离开收件箱的会话清除稍后状态，但绝不自动移动服务端邮件。
- **退出与睡眠**：没有常驻后台服务或系统通知。应用运行时每 15 秒检查，回到窗口及查询时也检查；关闭期间到期的项目在下次启动处理。物理睡眠／唤醒尚未单独验收。
- **标签**：名称最长 40 字符，去除首尾空白、规范 Unicode 后不允许同名（大小写不区分）；颜色为可自定的六位十六进制颜色。删除标签需界面确认，原邮件保留。选择中只有部分邮件带有某标签时显示半选状态，勾选为所有选中项添加。
- 本机操作在 SQLite 提交后返回 `succeeded`，无远端任务 ID。批量逐项返回结果，部分成功不伪装整批成功。取消置顶、结束稍后及移除标签是显式逆向操作，不使用上一轮远端任务的 `undo`。

## 实现范围

`app/src/services/mail-core/local-triage.ts` 管理三个本机表：

| 表 | 数据 |
| --- | --- |
| `PaperReedLocalThread` | `(accountId, threadId)` 的置顶、稍后时间、来信基准 |
| `PaperReedLocalLabel` | 共用的标签 ID、名称与颜色 |
| `PaperReedLocalThreadLabel` | 会话与本机标签的多对多关系 |

桌面已有的 `DatabaseStore` 连接是只读的。此模块复用已随应用内置的 `better-sqlite3`，在主窗口持有一个指向**同一邮件数据库文件**的本机写连接；只写这三个表，不经由上游可同步的 plugin metadata，也不创建另一份数据库、服务或远端任务队列。顺序受理本机写操作；每项状态更新是单条原子语句，删除标签及关联放在同一事务。实验表不修改上游 `user_version`；正式迁移及回滚仍需随最终底座确定。

稍后基准记录收件箱 `UIDVALIDITY`、`UIDNEXT` 与当时已有成员 ID。新同步成员需要超过原游标且来自外部发件人才会解除稍后；历史低 UID 补齐不算新来信。没有可用同步游标时明确拒绝稍后；`UIDVALIDITY` 改变后保留到期计时，不猜测新来信。

GUI 与 MCP 共用 `changeLocalMail`、`localStates`、`editLocalLabel`；列表复用已有查询入口，并在 SQL 层施加本机视图和置顶优先排序。CLI 仍只连桌面 MCP，不直接访问 SQLite。

## 权限与 CLI

- 本机邮件操作仍需整理／写权限，并校验显式账号、会话和被排除文件夹。读取状态也校验当前范围。
- 全局标签词汇可以只读列出，不包含邮件内容或成员计数。创建／改名／改色／删除全局标签需要全部已连接账号和文件夹的写权限，防止受限 Agent 修改其他账号使用的标签；给已授权会话添加／移除现有标签不要求全局权限。
- 命令：`pin`、`unpin`、`snooze`、`unsnooze`、`local-state`、`local-list`、`labels`、`label-create`、`label-update`、`label-delete`、`label-add`、`label-remove`。JSON 示例见 [CLI 使用说明](../cli/README.md)。

## 已执行验证

```sh
PAPER_REED_TRIAGE_CHECK=1 sandbox-exec -f research/harness/loopback-only.sb \
  research/.local/venv/bin/python research/harness/check-compose-handoff.py \
  --upstream research/.local/Mailspring --controls
```

在独立配置目录、实际 Electron 窗口、生产 MCP 端点、真实 CLI 进程和原生同步引擎上运行，网络仅允许回环地址。

通过：分页前置顶排序、GUI 取消置顶；标签创建／改名／改色／移除／删除、重复名拒绝、筛选和混合选择；稍后取消、定时到期；**关闭整个桌面、等待到期、重新启动**后状态恢复；阅读页稍后后仍可取消；本机标签视图的 Agent 交接；Escape 关闭局部选择器并保留勾选；逐项错误、账号错配、只读权限及排除文件夹校验；紧凑布局。

真实 IMAP APPEND 及原生同步验证了自己的回复不唤回、外部回复唤回。历史补齐用隔离数据库中的“已有低 UID 成员未出现在基准快照”场景验证，不冒充完整服务商历史同步验收。移动到废纸篓后清除稍后，未恢复收件箱。置顶、标签、稍后执行前后对比非草稿 Message 行，确认原星标、已读及位置均未改变。

另通过上一轮收件箱与搜索整套回归、TypeScript 检查、仓库基础检查和补丁重放。预期及实际 SMTP 提交均为 **0**；测试中两封回复由本机 IMAP 夹具注入，并非通过发件功能发送。

首轮发现只读数据库连接不能写表，已改为上述同库本机写连接；后续未扩大原邮件写权限。标签移除后选择器会关闭，测试改用点击后检查实际状态，避免等待已卸载的复选框。

## 尚未覆盖

- 没有跨设备同步、系统通知、关闭应用后的定时进程，也没有将邮件规则或 AI 自动分类接到本机标签。
- 目前验证了单个文件夹型 IMAP 测试账号；Gmail、Outlook / Graph、多真实账号、真实断网恢复及物理睡眠尚未验收。没有同步游标的账号会拒绝稍后。
- UID 基准基于最近同步状态：离线期间已到达但尚未看到的邮件，之后同步时可能视为新来信；从其他位置导入一个此前未知成员并获得新 UID，也可能唤回。UIDVALIDITY 改变后本轮只保证计时恢复。
- 已验证同一数据库完整重启后会话引用稳定；清空数据库、重建账号和引擎重新合并／拆分会话后的本机状态迁移尚未完成，不宣称任意重建后都能保留。
- 还没有本机操作历史撤销或编辑版本冲突合并。单项设置／添加／移除可重复执行；重复“稍后”会重新建立来信基准，不是持久请求账本的重试语义。
