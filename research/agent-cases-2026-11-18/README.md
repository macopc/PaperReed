# 从已有 CLI 开始的八个邮箱任务

2026-11-18 在本机运行 Paper Reed 0.0.1 arm64 构建、原生 mailsync、两个 loopback IMAP/SMTP 邮箱。运行时使用与 v0.0.1 对应的本地测试包，没有重新下载签名发行包。发信只进入测试服务器。

每个场景由独立的 Codex CLI 0.170.0 会话实际执行，使用本机默认模型配置 gpt-6.1-sol。每个会话获得用户任务和 CLI 路径；草稿交接额外附带账号及草稿引用。工具输出来自已安装的随包 CLI。套在入口外的记录器保存原始调用和返回，两次故障注入在下文标明。每个变体运行一次，没有统计模型成功率。预跑的记录器因沙盒拒绝日志写入而失败，已修复后重新运行，预跑不计入数据。

|任务|CLI 调用（含帮助）|通过依据与观察|
|---|---:|---|
|1 发现账号|2|返回两个邮箱。两个显示名相同，Agent 根据地址判断工作账号，并明确告诉用户判断依据。|
|2 查供应商交期|7|从旧方案、已更新订单和另一张订单中选中 PO-418，答出 12 月 9 日，并引用最新原文。|
|3 今日待回复|11|在六个当天相关会话中选中签核、预算两项。识别出已回复的门禁申请和知会邮件，并区分今天 15:00、周五两个期限。知会样本通过正文表明用途，本轮没有单测仅凭 Cc 头判断。|
|4 起草回复|12|正确会话下仅一封回复草稿，收件人正确，正文同意交期并询问发货时间。用独立启动的桌面窗口打开缓存副本核对可审阅性。首次建稿回执较短，Agent 又把相同正文写了一次，再读取确认。|
|5 修改第二段|5 / 7|普通和并发各一次。并发变体在 Agent 第一次读出草稿后，由另一个调用方通过同一草稿服务修改第一段日期，再交回旧读数。Agent 收到 draft-conflict 后重读再写。最终第一段是用户新日期 12 日，第二段更委婉，原收件人、第三段及附件保留。并发输入模拟的是已保存的用户编辑。|
|6 报价附件|13|分辨 v1 和 v2、读出新版总价 USD 14,360，并只把 v2 附到采购草稿。磁盘中的附件字节与输入材料 SHA256 一致。本次为可读取的文本附件。|
|7 整理并纠正|20|先归档两封通知，再单独恢复验收通知。IMAP 端仅部署通知在 Archive，验收通知及待签核邮件在 Inbox。本轮在一段提示中先后给出两条指令；调用记录显示实际执行了中间归档。中文“项目 A”查询英文标题为空，退回宽查后成功；accounts 带空 JSON 也产生一次参数错误。|
|8 发送已审草稿|6 / 8|两封独立测试草稿分别测正常和丢回执。丢回执变体在真实 CLI 获得 queued 后丢弃 stdout，给 Agent 一个连接中断错误。它以相同 requestId 重放，随后查询原 operationId。实际两笔发送各有一个已发送副本，工作 SMTP 共 2 封，个人 SMTP 为 0。未模拟 SMTP 服务商在 DATA 后断开。|

共 10 个有效会话，91 次 CLI 调用中 38 次是帮助；计数包含总帮助和命令示例，不含并发编辑、记录器或验收脚本。没有向参与执行的会话追加人工答案。任务间共享一套模拟邮箱，发送使用不同草稿。此轮不估计大邮箱搜索召回，也不推断其他模型的表现。

## 建议优先评审

1. 让丢失首个发送回执的恢复步骤可发现。现有帮助要求按 operationId 查询，首次回执丢失时调用方只握有 requestId。本次同键重放安全地取回原结果；适合先把这条已有路径写进命令帮助。
2. 对 reply 草稿回执补充可供核对的信息，或在命令帮助中明确正文已写入、如何只读核对。本轮观察到一次相同正文的额外写入。
3. 给搜索帮助补充当前支持的语法和空结果的缩小／放宽策略。账号、冲突、附件等现有行为先保留。先复测中英文混合的大邮箱，再决定是否需要改变搜索实现。
