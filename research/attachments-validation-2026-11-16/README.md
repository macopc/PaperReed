# 附件、CLI 写信闭环与账号颜色

2026-11-16。接在 0019 后的桌面补丁 [0020](../patches/0020-attachments-cli-compose.patch)，不修改原生引擎，不新增服务、数据表或调度器。仍是实验客户端，真实服务商未验收。

## Before / After / Why

| Before | After | Why |
| --- | --- | --- |
| CLI 只修改主题／正文，附件读取与回复建稿未暴露 | 可编辑 To/Cc/Bcc、回复／回复全部、读取和增删附件 | 让 Agent 完成准备草稿、交给 GUI 审阅和提交发送的完整流程 |
| 含附件的冲突草稿无法另存副本 | 严格复制所有附件，保留内嵌图片的 CID；失败不宣称副本已保存 | 保住未保存编辑与对应附件，不遗漏文件 |
| 移除附件立即删除文件；发送沿用草稿附件引用 | 移除保留缓存；恢复副本和发送任务各自持有新文件 ID 与独立字节 | 其他窗口或 Agent 的编辑不会破坏旧版本和发送内容 |
| 附件还在复制时可能离开编辑器 | 切换页面、关闭和发送等待当前附件添加完成，再保存 | 避免附件添加中途丢失 |
| 设置中的账号颜色与列表固定色板脱节 | 列表头像边框优先使用保存的账号颜色，全部／单账号范围一致 | 使用户自定义的账号辨识保持一致 |

## 实现边界

- `mail-core` 继续统一保存修订与发送结果。CLI 修改收件人和附件最终走已有原生草稿修订检查；不直接写邮件数据库，不改变发送账号。清空收件人与省略字段含义不同。
- 新 `draft-files.ts` 复用原附件目录与 File 模型，提供严格文件导入／复制。GUI 添加与 CLI 添加共用复制及总量检查；恢复和发送副本也走这条路径。每封草稿最多 25,000,000 字节的附件。
- 文件添加完成后才产生可保存的附件引用，先复制再提交修订。发送先复制附件，再交由原生引擎受理并锁定草稿修订。缺文件、超限或修订冲突都不允许静默少发附件。
- 新创建的本机附件有精确 `localFilename`，不得使用“目录中唯一文件”作为替代。旧服务端附件仍保留上游文件名兼容逻辑。
- 内嵌图片复制保留 contentId，正文无需重写。CLI 移除仍被正文引用的内嵌附件会报错。
- 新 CLI：`attachment-get`、`draft-reply`、`draft-attach`、`draft-detach`；`draft-update` 扩展收件人字段。参数和工作流见 [CLI 说明](../cli/README.md)。
- GUI 中已有附件展示、打开／下载组件继续复用。当前改动不增加附件面板或重做写信版式。

## 验证

运行真实 Electron 窗口、正式 MCP 入口、独立 CLI 进程、自编译原生引擎，以及隔离的本机 IMAP / SMTP 服务。所有账号、邮件和文件都是测试夹具；网络仅允许回环地址。

```sh
PAPER_REED_ATTACHMENTS_CHECK=1 sandbox-exec -f research/harness/loopback-only.sb \
  research/.local/venv/bin/python research/harness/check-compose-handoff.py \
  --upstream research/.local/Mailspring --controls
```

检查覆盖：

- 收到附件的读取、GUI／CLI 附件添加和移除、收件人修改与清空、无效地址和空收件人发送拒绝。
- 旧修订、目录／相对路径、单文件和累计大小上限、只读权限、错误账号、附件所在文件夹被排除。
- CLI 刷新干净编辑器；未保存 GUI 编辑与 CLI 移除附件冲突后，另存独立附件副本、载入原稿、重启后重新打开副本。
- 内嵌 CID 复制和仍在使用时的移除拒绝；附件复制中的页面切换等待；精确文件缺失时读取／发送失败。
- GUI 发送含附件恢复副本；CLI 回复全部并附加收到的文件，查询发送结果并用同一 requestId 重试。
- SMTP 实际投递数为 **2**。解析真实 MIME，检查附件字节、最终收件人、Bcc 不出现在邮件头、In-Reply-To 和 References。
- 发送快照生成后、原生任务入队前，测试钩子改写旧草稿附件文件。实际 SMTP 附件仍等于快照前内容；未替换发送器或伪造发送结果。
- 设置页修改账号颜色，检查统一收件箱、单账号范围及重启后的边框颜色。

附件复制等待用可释放的文件导入边界模拟慢磁盘，释放后仍执行真实复制和保存。其余邮件修改通过产品接口；测试不直接改邮件表。

## 限制

- 只验证本机文件夹型 IMAP / SMTP，不代表 Gmail / Outlook、Graph、跨设备草稿或真实附件大小限制已验收。正文中的 CID 保留已验证，复杂邮件的所有内嵌图渲染组合没有穷举。
- 为保护其他窗口的未保存编辑，移除／丢弃的本机草稿附件不会立即物理删除；失败提交也可能保留未引用副本。暂未加入垃圾回收，磁盘用量可能累积。已成功发送任务自己的附件快照沿用发送成功后的清理路径。
- 文件快照防止通过原文件或其他草稿引用改动发送内容，不承诺断电时文件系统持久性，也不隔离具有本机文件访问权的程序对内部缓存的直接破坏。
- 当前 CLI 支持新建、回复、回复全部及其附件操作；尚未新增转发命令、修改发件身份或附件下载目录管理。
- 完整第三方 Agent 客户端接入、签名公证和正式安装包仍属后续工作。
