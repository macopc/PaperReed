本轮补齐实验工作台的搜索、批量整理及 CLI 接口。截图来自独立配置目录中的 macOS Electron 窗口，连接本机 IMAP / SMTP 测试服务；不是设计稿，也不代表真实服务商兼容验收完成。

## Before / After / Why

| Before | After | Why |
| --- | --- | --- |
| 收件箱主要支持读信和写信 | 搜索、仅未读、逐项选择、当前已加载结果全选 | 支撑每天筛选和整理邮件 |
| 没有批量整理入口 | 选择后才出现已读、未读、归档、垃圾邮件、废纸篓；垃圾邮件或废纸篓可移回收件箱 | 保留安静的默认列表，按上下文显示操作 |
| 列表交接偏向整个邮箱 | 搜索交接保留查询；勾选交接提供精确的会话引用 | Agent 沿用用户选中的范围 |
| CLI 主要读信、操作草稿和发送 | 增加整理、任务状态和撤销命令 | GUI / CLI 共用业务规则和原生任务队列 |
| 提交动作缺少整理回执 | 分别显示排队、同步、成功、失败和可撤销状态 | 不把已排队当成远端已完成，部分失败仍保留逐项结果 |

## 交互

- 搜索在当前账号范围的本地缓存中执行，不局限于当前文件夹；支持现有解析器的查询语法。回到列表保留查询，清除搜索恢复文件夹范围。
- 初次加载 50 个会话，最多加载 100 个；“全选”只选择已加载结果。更多结果需收窄查询，不隐式操作尚未看到的邮件。
- `⌘F` 聚焦搜索，`J/K` 移动列表焦点，`X` 勾选，`E` 归档已选项，`Esc` 清除选择。输入框、可编辑正文和输入法组合状态不触发这些列表快捷键。
- 批量操作保留逐项回执，失败可展开；成功且能够精确恢复时提供本批撤销。每个操作固定提交时的邮件 ID，后来进入同一会话的新邮件不受原动作或其撤销影响。
- 窄窗口仍保留选择、操作和回执。没有增加常驻图标工具条或新的全局命令面板。

## 共用实现

新增 `app/src/services/mail-core/inbox.ts`，复用现有查询解析器、授权模型、`ChangeUnreadTask` / `ChangeFolderTask` 及原生 Task 存储。没有另建同步服务、索引、数据库或调度器。

`queryInbox` 提供 GUI / 普通 CLI 搜索的公共入口。`organizeMail` 接收明确的账号、会话及请求 ID；`mailTaskStatus` 和 `undoMail` 提供整理状态与逆操作。MCP 新增 `organize_mail`、`mail_task_status`、`undo_mail_task`，CLI 命令见 [使用说明](../cli/README.md)。既有 MCP 整理工具仍保留，本轮没有将它们全部迁移到新入口。

为避免原生引擎优先按会话重新展开成员，带 Paper Reed 整理元数据的任务序列化时省略 `threadIds`，使用固定的 `messageIds`。文件夹撤销只使用引擎记录的实际原始位置，不猜源文件夹，也不接入上游近似的全局撤销。

另执行桌面 TypeScript 检查、仓库基础检查和桌面补丁逐个重放。重放文件逐字节匹配实际测试 checkout，规范 CLI 源文件与桌面内置副本一致。

## 边界

- 当前是文件夹型 IMAP 的整理适配。Gmail 标签型 Inbox 的归档及移回尚未接入精确标签快照，界面禁用不支持的操作；未宣称完成 Gmail、多服务商或双真实账号验证。
- 搜索只覆盖已同步到本地的数据，不是服务端全量搜索。自定义标签、置顶、稍后处理和分类不在本轮范围。
- 整理状态复用上游有界 Task 历史（完成／取消任务通常保留最近约 100 项）。同请求重试与撤销只在任务仍保留时可靠；它不是发送操作的持久账本。`operation-not-found` 不证明操作失败，不能据此换请求 ID 盲重试。
- `unchanged` 不创建持久任务；整理请求没有跨清理周期的永久去重承诺。
- 如果同一邮件在多个文件夹副本中的已读标志不一致，可设置状态，但本轮不提供无法精确恢复的撤销。撤销不是任意历史版本恢复，也不保证跨后续外部编辑的合并。
- 权限在入口及异步读取后检查；未新增原生引擎执行前的撤权机制。只读与排除文件夹测试不等于这一机制已完成。
- 不提供永久删除、清空垃圾箱、系统通知或后台稍后提醒。CLI 手动粘贴任务的交接已验证，第三方 Agent 客户端仍需逐一验收。
